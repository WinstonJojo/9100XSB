# 137 变更记录：网页现行实现

本文件仅记录 `130` 至 `136` 现行实现副本的事实修订和与之对应的网站源码变化；历史原件仍按其原有日期与语境保留。

## 2026-09-19：公网天气链路复核与错误反馈

### 观察到的事实

1. 首次在 `https://smrtwatering.com/#configure` 选择“中国 → 上海市”后，天气查询失败，页面提示无法取得完整天气数据，并阻止配置生成。
2. 随后使用新的地点令牌直接调用线上天气接口 6 次，均返回 HTTP 200，单次总耗时约 1.35–3.38 秒；Open-Meteo 的同一上海请求也返回 HTTP 200。
3. 因此，首次失败不能描述为当前持续故障；现有证据支持“瞬时上游、网络、超时、限流或异常响应之一”，但旧代码将这些情况合并为同一条 503 错误，未保留足以唯一归因的异常类别。

### 源码修订

网站源码的天气查询改为：对超时、网络错误、429 和 5xx 的只读天气请求最多重试一次；两次均重新访问上游，不使用缓存或静态天气。失败响应新增安全诊断编号：`upstream_timeout`、`upstream_network_error`、`upstream_rate_limited`、`upstream_http_error`、`upstream_invalid_response`。

配置页新增用户可见反馈：显示失败原因、建议操作、诊断编号和可用的 HTTP 状态；不显示地点令牌、精确坐标、用户配置或内部异常详情。系统日志只保留诊断类别、尝试次数和耗时。
