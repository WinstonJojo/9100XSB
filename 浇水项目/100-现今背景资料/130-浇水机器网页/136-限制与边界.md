# 136 限制与边界：当前演示部署

> 原件：`../136-限制与边界.md`。本副本按当前网站实现及 2026-09-17 上线观察修订。依据见 [[130-阅读说明]]。

## 服务与数据

- Render 免费 Docker 服务已上线，但没有为本次实例配置持久磁盘。SQLite 位于 `/app/instance/system.sqlite3`；实例更换后本地运行数据可能丢失。代码会在缺少数据时从镜像内的植物和系数 JSON 初始化，**尚未在生产实例专门模拟重建验收**。
- `APP_PROFILE=preview` 禁止植物库写入和 Git 快照，适合短期演示；进程统计与维护日志不应视作长期审计资料。切换 `standard` 前必须先设计持久化与备份。
- 用户填写的配置主要在浏览器页面内存；导出文件需用户主动保存。当前 Flask 不设用户账号、项目、设备和配置历史表。
- SQLite 与免费实例资源不适合按多人高并发、长期稳定运营系统来承诺容量或可用性。

## 外部服务与配置生成

- 地点列表经后端访问外部数据源，天气来自 Open-Meteo。旧笔记中的 `OWM_API_KEY` 和“天气失败后静态地点降级”不适用于当前实现。外部服务失败、天气异常或签名地点失效时应明确报错，停止生成新配置。
- 地点目录、行政区划和地图坐标由不同上游维护，可能存在版本差异；天气是城市代表坐标的短期数据，不是精确到花盆的测量。
- 水量、阈值、脉冲等参数是工程建议，仍需植物、泵流量、继电器电平、电源与传感器实测校准。网页的参数范围不能代替固件安全校验。

## 浏览器与硬件

- 实体设备操作依赖用户设备附近的浏览器 Web Bluetooth、HTTPS、安全上下文、用户授权和设备可连接状态；网站托管在 Render 不等于云端可远程唤醒或控制设备。
- SWS-BLE 当前使用公开开发密钥的 nonce 哈希作为草案认证，不是量产级身份认证或加密；CRC32 只检测传输损坏。正式硬件产品需重新评估设备认证和密钥分发。
- 模拟设备只验证软件交互。实际 ESP32 与传感器、水泵、执行器、供电的整机联调仍待完成；不能把模拟结果写成真实浇水成功。

## 管理端与网络安全

- `admin.smrtwatering.com` 已显示管理员密钥登录页；管理 API 需要管理 Host 与 Bearer 密钥。生产密钥存放于 Render 环境变量，笔记和 GitHub 均不记录明文。
- Cloudflare Access 应用和管理员邮箱策略尚未创建；Cloudflare DNS 中 `admin` 仍为“仅 DNS”。当前不应声称有 Cloudflare 身份登录保护。
- Render 原始 `onrender.com` 地址仍启用。将来加入 Access 后，应继续保留应用自己的 Host 与密钥校验，并验证实际请求路径、回源和 HTTPS。
- 2026-09-17 仅确认管理密钥表单出现，未用生产密钥测试登录后的完整后台。后续验收需分别测未授权与授权状态。

## 旧笔记的适用范围

原件中 SoftAP 同步服务器、云端项目表、Arduino 固件生成模板、`OWM_API_KEY` 和设备 HTTP 拉取接口等描述，属于旧方案或设备侧的独立实现，不能作为此次上线网站的现行能力清单。若需求仍有效，应先确认要保留的业务目标，再按当前代码设计新接口与迁移方案。
