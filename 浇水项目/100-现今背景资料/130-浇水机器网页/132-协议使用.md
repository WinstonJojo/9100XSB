# 132 协议使用：当前网站、地点与 BLE

> 原件：`../132-协议使用.md`。旧版 `SWS-HS`、SoftAP `/uploadConfig`、云端 HTTP 设备同步示例保留在原件供历史对照；本副本记录当前网站源码中的链路。依据见 [[130-阅读说明]]。

## 三类数据边界

1. **Flask JSON API**：浏览器与同源后端交互，读取植物、外部地点和天气，生成/导入/导出配置。公开 API 不是云端用户配置仓库。
2. **地点选择令牌**：外部列表项由后端签发 `selectionToken`；最终地点确认后得到 `locationToken`。生成配置时后端验证最终令牌，不信任客户端自填坐标。令牌在页面内存中使用，有效期一小时；签名不等于加密。
3. **SWS-BLE 1.0**：浏览器与附近设备直接通信。当前网页实现 JSON 消息分包、base64、整消息 CRC32、消息编号和请求响应匹配；不是通过 Render 服务转发蓝牙数据。

## 配置 JSON

后端 `/api/configurations/generate` 接收植物 ID、地点令牌、栽培和供水场景等输入，返回配置、参数、环境解释与提示。当前配置格式使用 `deviceModel: ESP32-WATER-C3`、`params`、`display`、`revision` 等字段；以当前源码的 `engine/validation.py` 和 `docs/api.md` 为准，不能直接上传原件中的旧 `SWS-CFG` 或 `snake_case` 云同步示例。

`/api/configurations/import` 校验 JSON 和版本；`/api/configurations/export` 输出规范配置文件。导入成功表示网页参数校验通过，设备仍须再次校验型号、版本、认证和安全范围。配置和用户场景不会自动存入服务器的项目表；浏览器当前状态刷新后会清空，用户需要主动导出文件。

## SWS-BLE 1.0 的网页实现

- 握手需匹配协议 `SWS-BLE`、版本 `1.0`、设备型号 `ESP32-C3`，并检查设备 ID、nonce、固件版本和模式能力。
- 请求消息包含 `id`、`protocol`、`protocolVersion`、`action`、`payload`。默认按 120 字节载荷分包，再通过 BLE 带响应写入发送；固件声明容量可降低这些限制。
- 分包帧携带 `id`、`index`、`total`、`checksum`、`data`，以换行分隔 JSON；`checksum` 是整消息 CRC32，用于传输完整性检测，不是安全签名。
- 当前网页使用 `SHA-256(nonce + SWS2026C3)` 的**公开开发密钥**作为握手认证草案。该值写在公开前端代码里，不能视为量产密钥、加密或强身份保证。
- 状态、历史、读取配置等只读操作在特定超时/损坏条件下可重试；配置写入、模式切换等操作不自动重放。写入超时后结果可能未知，应先读回设备状态。
- 使用 Web Bluetooth 需要浏览器支持、HTTPS 安全上下文、用户授权及设备在附近且处于可连接状态。网站上线并不证明实物连接已通过。

## 版本和安全校验

协议版本、配置格式版本、固件版本、知识库版本、设备 `revision` 分开管理。网页会拒绝旧于或等于设备当前版本的待发送配置。后端给出的阈值、脉冲时长等应用层范围仍须与实际固件上限及泵、继电器、电源参数核对；危险操作应由固件再次校验。

当前项目没有可据此声称“设备可通过云端 HTTP 自动同步配置”的 Flask 路由。若日后添加 Wi-Fi 远程同步，应单独定义设备身份、授权、离线行为与版本冲突规则。
