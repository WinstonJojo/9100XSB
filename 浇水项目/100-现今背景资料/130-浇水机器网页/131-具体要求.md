# 131 具体要求：现行网站实现与上线状态

> 原件：`../131-具体要求.md`。本副本按当前网站源码修订，供继续开发；不抹除原件中更早的项目设想。依据见 [[130-阅读说明]]。

## 网页体系分层

当前交付的 Flask 网站提供公共页面和独立管理页面。浏览器通过 HTTPS 访问 Flask 服务，配置计算在后端完成；浏览器使用 Web Bluetooth 与附近的 ESP32-C3 直接通信。ESP32 SoftAP 本地网页若存在，属于设备固件自身的另一条链路，不由本次 Render 网站提供。

## 公共网站的当前要求

1. 展示首页、产品介绍、个性化库编译和硬件情况查看页面。
2. 从植物库选择植物；按国家、省份/直辖市、城市联动选择地点。地点列表来自外部服务，选定后查询天气。
3. 输入栽培方式、花盆容量、光照、供水变体、水箱等场景信息，由后端计算推荐参数与设备配置。
4. 在页面内预览生成结果，支持配置 JSON 导入与主动导出；配置刷新后不应被误以为仍保存在云端。
5. 浏览器在用户主动操作并授权后，通过 BLE 握手、发送/读取配置、查看状态与历史、切换模式，以及执行需确认的设备操作。
6. 模拟设备入口可用于软件演示，须持续标明“模拟”；模拟成功不代表实体设备联调完成。
7. 线上错误、免费实例冷启动与外部地点/天气服务失败应给出可理解的提示；业务写入和设备操作不自动重放。


## 管理端的当前要求与状态

- 管理入口使用 `https://admin.smrtwatering.com/`，与公共站点共用 Render 服务，由 `ADMIN_HOSTS` 区分页面。
- 管理 API 需要该 Host 和 `Authorization: Bearer <ADMIN_TOKEN>`。2026-09-17 浏览器已看到管理员密钥表单，尚未验证输入密钥后的所有功能。
- 本次部署采用 `APP_PROFILE=preview`：健康、统计、日志、植物库与公式可读；植物库修改和 Git 快照受后端 403 限制。
- Cloudflare Access 的额外邮箱登录层尚未创建；不能写成已受 Access 保护。

## 部署要求与实测

GitHub 私有仓库 `WinstonJojo/smrtwatering` 的 `main` 提供源码；Render 免费 Docker Web Service 运行 Flask + SQLite；Cloudflare 管理三条“仅 DNS”CNAME。`smrtwatering.com`、`www.smrtwatering.com` 和 `admin.smrtwatering.com` 均在 Render 显示 `Verified`、`Certificate Issued`。当时浏览器确认主域名、`www` 跳转和管理密钥页可打开。

Render 免费实例未配置持久磁盘，当前 `preview` 适合短期演示。需要长期保存管理员修改、日志或云端用户/设备资料时，必须先增加持久化、备份、权限和数据生命周期设计，再开放相应写功能。

## 仍需验证

- 线上完整地点、天气、配置生成、导入导出流程。
- 管理端使用生产密钥后的只读页面与接口行为。
- 真正的 ESP32-C3 BLE 配置发送、读回、模式操作与硬件安全边界。
- 免费实例重建后初始知识库的恢复，以及长时间运行与外部服务故障表现。

## 2026-09-19 公网复核补充

本次直接打开 `https://smrtwatering.com/#configure`，完成“中国 → 上海市”的地点选择；地点坐标和自动季节能够显示，但首次天气查询失败，页面提示“无法取得完整的外部天气数据”，并保持“分析并生成配置”禁用。点击“重新查询天气”后仍失败。

同日使用新的地点令牌直接请求线上天气接口 6 次，均返回 HTTP 200，耗时约 1.35–3.38 秒。因此该失败应记录为一次已观察到的瞬时外部天气链路故障，而不是“天气服务持续不可用”。“代码具备配置生成接口”“某次公网调用成功”与“长期稳定可用”仍必须分开记录。
