# 2026-09-19 网页天气链路与错误反馈变更

> 记录范围：`100-现今背景资料/130-浇水机器网页` 的事实核对及其对应网页源码。本文是历史变更记录，不改变原有背景资料的日期和语境。

## 公网复核结论

1. 首次在 `https://smrtwatering.com/#configure` 选择“中国 → 上海市”后，天气查询失败，页面提示无法取得完整天气数据，并阻止配置生成。
2. 同日使用新的地点令牌直接调用线上天气接口 6 次，均返回 HTTP 200，单次总耗时约 1.35–3.38 秒；Open-Meteo 的同一上海请求也返回 HTTP 200。
3. 因此，首次失败应记录为已观察到的瞬时天气链路异常，不能写成持续故障。旧代码把上游、网络、超时、限流和异常响应合并为同一条 503 错误，未保留足以唯一归因的异常类别。

## 源码改动

- 天气查询对超时、网络错误、429 和 5xx 的只读请求最多重试一次；两次均重新访问上游，不使用缓存或静态天气。
- 失败响应新增安全诊断编号：`upstream_timeout`、`upstream_network_error`、`upstream_rate_limited`、`upstream_http_error`、`upstream_invalid_response`。
- 配置页显示失败原因、建议操作、诊断编号和可用的 HTTP 状态；不会显示地点令牌、精确坐标、用户配置或内部异常详情。
- 系统日志只保留诊断类别、尝试次数和耗时。
